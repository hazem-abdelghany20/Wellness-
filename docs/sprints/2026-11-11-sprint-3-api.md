# Sprint 3 foundation — API for the UI builders

Backend for: routine reminders (Web Push), broadcasts at the set time + audio, teams admin, privacy folding, and four fixes. Plan items 9, 13, 16, 18 (web part), 22 (upload side) of [sprint 2](2026-11-09-sprint-2-routines-and-libraries.md).

- SQL: `supabase/migrations/20261111000001_reminders_broadcasts_teams.sql` (idempotent, paste into the live SQL editor)
- Edge function: `supabase/functions/send-reminders/` (`index.ts` + pure `payload.ts`)
- Snippets: `supabase/snippets/reminders_setup_after_deploy.sql`, `supabase/snippets/cleanup_test_data_2026-11-09.sql`
- Libs: `src/lib/push.ts`, `src/lib/supabase-teams.ts`, `src/lib/supabase-broadcasts.ts`, additions in `src/lib/supabase-routines.ts`
- Service worker: `public/sw.js` (v4: `push`, `notificationclick`, `pushsubscriptionchange`), badge `public/badge-96.png`

Every lib function throws the Supabase error as-is; `error.message` is the SQL code (e.g. `team_not_empty`), `error.details` carries extra data where noted. `friendlyError()` / `friendlyErrorI18n()` in `src/lib/errors.ts` map the new codes to EN / AR copy.

## Employee app

### Reminders switch (Me / Today) — `src/lib/push.ts`

| Function | Purpose | Returns |
|---|---|---|
| `getPushSupport()` | Can this browser get push, and if not why | `{ supported, reason, ios, standalone }`; `reason`: `ios_needs_install` (iPhone Safari tab → show the 3-step “Add to Home Screen” card), `native_app` (Capacitor app — item 8), `no_push_manager`, `no_service_worker`, `no_notification`, `insecure`, `no_vapid_key` |
| `getPushState()` | Switch state without prompting | `{ state: 'unsupported' \| 'denied' \| 'prompt' \| 'unsubscribed' \| 'subscribed', permission, endpoint, support }` |
| `enableRoutineReminders({ lang })` | **On the tap**: ask permission, subscribe, save the device, `routine_reminders = true` | `MyPrefs` |
| `disableRoutineReminders({ unsubscribe? })` | `routine_reminders = false` (device stays subscribed so HR broadcasts still push; `unsubscribe: true` stops all push on this device) | `MyPrefs` |
| `subscribePush({ lang })` / `unsubscribePush()` | The device part alone | saved row / `boolean` |
| `refreshPushSubscription({ lang })` | Call once after sign-in / app start: re-saves an existing subscription (new account on the same phone, rotated endpoint, language). Never prompts | row or `null` |
| `isIOS()`, `isStandalone()`, `getVapidPublicKey()`, `urlBase64ToUint8Array()` | helpers | |

Errors: `push_denied` (blocked — only browser settings can undo), `push_dismissed` (prompt closed), `push_unsupported` (`error.reason` as above), `push_no_key`, `push_no_service_worker`, `invalid_subscription`.

Per-item mute stays `setItemMuted(itemId, muted)` (sprint 2). A reminder goes at the item's time (company time) on the routine's workdays, only if the item isn't ticked or muted, once per item per day, to every device of the person (max 10 kept).

**Tap on a notification** opens / focuses the app at `/?open=today&item=<id>` (reminder) or `/?open=notifs&broadcast=<id>` (broadcast) and posts `{ type: 'OPEN_URL', url }` to an open window. The employee UI should read `open` from the URL on load and listen for that message (`navigator.serviceWorker.addEventListener('message', …)`) to switch tab. On `{ type: 'PUSH_SUBSCRIPTION_CHANGED' }` call `refreshPushSubscription()`.

`days[].items[]` now also have `exercise` (same shape as `TodayItem.exercise`: name, sets, body areas, media fields — play with `resolveMedia(item.exercise)`), `note_en`, `note_ar`.

## HR portal

### Broadcasts — `src/lib/supabase-broadcasts.ts`
The existing `scheduleBroadcast / cancelBroadcast / listBroadcasts` in `supabase-hr.ts` already call the new RPCs (old calls only as a fallback before the SQL is live), so today's screen stops sending at once.

| Function | Purpose | Args | Returns |
|---|---|---|---|
| `listBroadcasts(limit = 100)` | Company broadcasts, newest first | | `Broadcast[]` |
| `saveBroadcast(input)` | Create (no `id`) or edit while `scheduled` | `{ id?, title_en, title_ar?, body_en?, body_ar?, scope: 'all' \| 'team', team_id?, scheduled_at? (ISO; missing / past = now), audio?: { path, mime, duration_s } \| null }` — `audio: null` removes it, left out keeps it | `Broadcast` |
| `cancelBroadcast(id)` | Cancel before it goes | | `Broadcast` |
| `uploadBroadcastAudio(file, { onProgress, signal })` | Upload a voice note / podcast to `company-media/{company}/broadcasts/` with progress; reads the length | | `{ path, mime, duration_s, upload }` → pass as `audio` |
| `audioMimeOf(file)`, `readAudioDuration(blob)` | helpers; picker `accept`: `AUDIO_ACCEPT` (in supabase-routines) | | |

`Broadcast`: row + `team_name`, `has_audio`, `deliver_at` (scheduled: when it will really go — quiet hours move a 21:00 one to 08:00; sent: `sent_at`), `recipients`, `push_sent`, `push_failed`, `media_*`. Status `scheduled → sent | cancelled`. Due now → delivered by the save itself; otherwise the per-minute job delivers it. Text or audio required. Audio: mp3 / m4a / webm / ogg (`audio/webm;codecs=opus` from MediaRecorder is accepted), ≤ 50 MB; prefer mp3 / m4a for iPhones.

Errors: `title_required`, `title_too_long` (160), `body_too_long` (2000), `body_required`, `bad_scope`, `team_not_found`, `bad_scheduled_at`, `bad_media_mime`, `bad_media_duration`, `media_path_outside_company`, `broadcast_not_found`, `broadcast_not_editable` (details = status), `broadcast_already_sent`, `bad_audio_type` / `too_large` (before upload).

### Settings — `setCompanySettings({ quiet_hours: boolean })`
New key `quiet_hours` (default on = HR broadcasts only 08:00–20:00 company time). `my_company_settings()` also returns `quiet_hours` and `quiet_window: { from: '20:00', to: '08:00' }`. (Reminders are the employee's own opt-in and follow the item times.)

### Teams — `src/lib/supabase-teams.ts` (HR / company admins)

| Function | Purpose | Returns |
|---|---|---|
| `listTeams()` | Teams by name with `members`, `leads[]`; plus `no_team` count | `{ teams, no_team }` |
| `createTeam(name, department?)` | Unique name per company (any case) | `Team` |
| `renameTeam(id, name?, department?)` | `name` null keeps; `department` undefined keeps, `''` / null clears | team row |
| `deleteTeam(id, { moveMembers? })` | Empty team, or move its people to “No team” first (its leads go back to employee) | `{ deleted, moved, leads_unset }` |
| `movePersonToTeam(userId, teamId \| null)`, `movePeopleToTeam(ids, teamId \| null)` | Move to a team / “No team”; a lead stays lead | `{ team_id, moved, user_ids }` |
| `setTeamLead(userId, lead = true)` | employee ⇄ manager (team lead). Takes effect in their app at the next token refresh (≤ 1 h) | `{ user_id, team_id, role, lead }` |

Errors: `team_name_taken`, `name_required`, `name_too_long` (80), `team_not_found`, `person_not_found` (details = id), `team_not_empty` (details = count), `team_in_use` (details = `routine,challenge,broadcast` — end / cancel what still runs for the team first), `protected_role` (HR / company / Wellness admins are never changed), `person_has_no_team` (a lead needs a team).

### Routine import: many videos at once — `src/lib/supabase-routines.ts`

1. `matchFilesToExercises(fileNames, exercises)` → `{ matched: { fileName: exerciseId }, unmatched: [] }` (case, punctuation, accents, Arabic harakat and the extension ignored; matches EN or AR names).
2. Upload each matched file with `uploadCompanyMedia(file, { folder: 'exercises', onProgress })`.
3. `setExercisesMedia(items, { overwrite = true })` once, items `{ id, ...mediaFieldsFrom(upload) }` (max 200) → `{ updated, skipped: [{ id, reason }] }`. Reasons: `exercise_not_found`, `public_item_read_only` (copy it first), `has_media` (overwrite false), `duplicate`, `bad_media_mime`, `media_path_outside_company`, …

### Reports: privacy folding
Wherever teams are shown under the 5-person floor, “company total − teams shown” can no longer expose a small group: when the hidden rest would be 1–4 people, the smallest shown teams are folded into it.
- `getRoutineReport()`: the `small: true` row is now “Other teams” (small teams + folded teams + no-team people under the floor). New `teams_folded` (count) and `breakdown_suppressed` (no team shown on its own) — show a line like “Some teams are grouped to protect privacy”.
- `getRecognitionBoard()`: folded teams just don't appear.
- HR Teams view (`hr_team_overview`) and `getTeamDrilldown()`: folded teams come back `suppressed: true` (drill-down also `folded: true`).
- `hr_habit_challenges()`: the default weekly habit shows status `'paused'` while a company-wide routine runs.

## Owner: deploy

1. Paste `supabase/migrations/20261111000001_reminders_broadcasts_teams.sql` into the live SQL editor and run it (enables `pg_cron` + `pg_net`, schedules `wellness-minute-tick`; broadcasts start arriving at their time right away, in-app).

3. `supabase functions deploy send-reminders --no-verify-jwt` and `supabase functions deploy hr-schedule-broadcast`.
4. `supabase secrets set CRON_SECRET=<hex> VAPID_PUBLIC_KEY=<pub> VAPID_PRIVATE_KEY=<priv> VAPID_SUBJECT=mailto:<contact>`.
5. Fill the two placeholders in `supabase/snippets/reminders_setup_after_deploy.sql` (functions URL `https://<ref>.supabase.co/functions/v1`, the same cron secret) and run it; its checks show `200 {"ok":true…}` in `net._http_response` within a minute.
6. Frontend build env (Amplify): `VITE_VAPID_PUBLIC_KEY=<pub>`; redeploy (new `sw.js` v4).
7. Optional, once: `supabase/snippets/cleanup_test_data_2026-11-09.sql` (lists, then deletes the test invites / test user / archived QA template).
