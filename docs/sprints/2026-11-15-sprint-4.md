## 2. API

Every function throws the Supabase error as-is; `error.message` is the SQL code. `friendlyError()` / `friendlyErrorI18n()` map the new codes.

### Employee app

**Today sections.** No new call. `getMyToday()` already returns `routines[]` (`id`, `title_*`, `note_*`, `day_title`, `source_file_*`) and `items[].routine_id`. Group items by `routine_id`.

**Challenges** (`src/lib/supabase.ts`)

| Function | Purpose | Returns |
|---|---|---|
| `getMyHabitChallenges()` | Every challenge running or coming up for me, running first (max 20). Falls back to the single one before the SQL is live. | `HabitChallengeState[]` |
| `logHabit(id, done)` | Unchanged. Refuses an automatic challenge with `challenge_is_automatic`. Re-read the list after it. | one state |

`HabitChallengeState` gains `auto_from_routine: boolean` and `routine_items: [{ id, title_en, title_ar, due_today, checked }]`. For an automatic challenge `can_log` is always false: show the items and send the person to Today.

**Everyone visible** (`src/lib/supabase-routines.ts`)
- `getMyPrefs().company.everyone_visible`: true = no opt-ins. `recognition_opt_in` / `share_with_hr` no longer matter while it is on.
- `getMyPrefs().visibility_notice_seen_at` + `setMyPrefs({ visibility_notice_seen: true })`: show the notice once.
- `getRecognitionBoard().me.opted_in` is true for everyone while it is on.

### HR portal

| Function | Purpose | Notes |
|---|---|---|
| `setCompanySettings({ everyone_visible: boolean })` | Everyone on the board and in the people list, no opt-in | `hr_people_view` reads true while it is on |
| `getRoutinePeople()` | now also `everyone: boolean` | lists every onboarded person while on |
| `setRoutineItemHidden(itemId, hidden = true)` | Hide / show one routine row | returns the routine; items carry `hidden_at`. Hidden = gone from Today, week view, reminders and due counts from today on |
| `scheduleChallenge(input)` (`supabase-hr.ts`) | Start a challenge with its own dates | `{ templateId? , title_en?, title_ar?, action_en?, action_ar?, routineItemIds?, startDate, endDate?, successDays?, teamId? }` → the challenge row + `workdays`, `success_days` |
| `cancelHabitChallenge(id)` | Cancels an upcoming one, **or ends a running one** | finished ones: `only_upcoming_can_be_cancelled` |
| `scheduleHabitChallenge(templateId, weekStart, teamId)` | Unchanged call; no longer blocked by another challenge in the same week | only the same template can't overlap itself |

`scheduleChallenge` rules: a template **or** a typed title; with `routineItemIds` (1–20 rows of this company's routines, not hidden) the challenge counts by itself; only Sun–Thu days count; default days needed = the template's, else 80% of the workdays, never more than the workdays.

Errors: `start_required`, `bad_dates` (end before start, or more than 5 weeks), `no_workdays`, `week_in_the_past`, `title_required`, `title_too_long` (80), `action_required`, `action_too_long` (600), `item_not_found`, `too_many_items` (20), `template_not_found`, `template_archived`, `team_not_found`, `habit_week_taken` (same challenge, same days, same people).

## 3. Rules worth knowing

- **Hide keeps history.** A row hidden on Tuesday still counts in Monday's numbers.
- **Automatic challenge day** = every linked row that is due that day is ticked. Untick one and the day stops counting. A day with no linked row due counts nothing.
- **Points.** A challenge day is still +10, a completed challenge +20, on top of the routine points. More challenges at once = more points to earn; HR decides.
- **Everyone visible** changes who appears, not what appears: names with what they did (ticks, full days, streaks). Never health, mood or check-ins. The 5-person floor on team numbers stays.
